The Problem

Existing agent memory is a black box

Can't prove what it believed

No timestamp, no WAL — you can't reconstruct what the agent knew at any past moment. Audit is impossible.

Can't retract safely

Deleting a fact leaves derived rules and skills silently orphaned. The agent keeps acting on stale knowledge.

Silent contradictions

"Rate limit is 100 rpm" and "Rate limit is 60 rpm" coexist. No system flags the conflict or demands resolution.

No rule lineage

Rules are stored as blobs. Nobody can answer: which observations produced this rule? What breaks if I change it?

Compliance is manual

Regulated industries need a paper trail. Every tool today requires you to build this audit layer yourself, on top.

Result

Autonomous agents are undeployable in finance, healthcare, legal — the sectors where persistent memory matters most.

What blocks wider adoption

Friction points

No TypeScript SDK HIGH

~50% of agent builders use TypeScript/Node. No SDK = no adoption from that half of the market.

No LangChain / LlamaIndex integration HIGH

Most developers build on frameworks. Mnema must be a memory plugin for those frameworks, not a standalone library.

No managed cloud option HIGH

Enterprises won't self-host a v0 library. They need an API endpoint, SLAs, and a dashboard.

Ollama required for LLM MEDIUM

Most developers default to OpenAI or Claude. Adding an OllamaLLM alternative removes this friction instantly.

What works

3-line SDK integration

client = MnemaClient(); client.observe(...); client.inject() — genuinely simple for Python devs.

Zero cloud dependency

Pure SQLite + local Ollama. Privacy-first teams and air-gapped environments can adopt immediately.

Hexagonal / pluggable architecture

Swapping LLM, embedder, or store is one constructor argument. Adapters don't touch core logic.

FastAPI compliance API

All audit surfaces are HTTP endpoints. Compliance officers can query without touching Python.
