The WAL — Immutable Belief Ledger

Core Architecture

Every change to an agent's knowledge — observing a new fact, revising an old one, retracting a wrong one — is written as an append-only event to a Write-Ahead Log (WAL). Nothing is ever deleted. Nothing is ever overwritten.

This is borrowed from database engineering (Postgres, Kafka) and applied — for the first time — to agent belief management.

# Every belief mutation produces a WAL event:
ASSERTION_RECORDED   → new belief entered
ASSERTION_SUPERSEDED → belief revised (old version preserved)
ASSERTION_RETRACTED  → belief withdrawn (still in history)
CONSOLIDATION_RUN    → sleep phase executed, digest produced
RELATIONSHIP_ASSERTED→ contradiction flagged
RELATIONSHIP_RESOLVED→ contradiction resolved with note
Why this matters: Every other memory system uses mutable databases — you can update and delete. That means you can never answer "what did the agent believe yesterday?" or "when exactly did this fact change?" The WAL makes those questions trivially answerable because the full history is always there.
vs. competitors
Zep uses bi-temporal timestamps (close, but no immutable event log). Mem0, MemGPT, LangMem: mutable stores — history is lost on update.

Assertions — Typed, Provenance-Linked Facts

Core Model

The atomic unit of knowledge in Mnema is not a string or an embedding — it is an Assertion: a structured object with identity, provenance, confidence, validity window, and status.

class Assertion:
    id: str              # content-addressed SHA-256 — same fact = same id
    statement: str       # "Rate limit is 60 rpm"
    subject: str         # "api"  (for subject-based retrieval)
    agent_id: str        # which agent owns this belief
    namespace: str       # logical partition (e.g. "weatherlib")
    status: active | superseded | retracted
    supersedes: str      # id of the assertion this replaced
    confidence: float    # 0.0–1.0 (default 0.85 from settings)
    valid_from: datetime # when this was true in the world
    valid_to: datetime   # when it stopped being true
    asserted_at: datetime# when we recorded it (transaction time)
    provenance: Provenance  # origin_type + source_id

The content-addressed ID means the same fact recorded twice gets the same ID — deduplication is structural, not a query. The supersedes chain tracks every revision so you can walk the full history of any belief.

Why this matters: Storing facts as raw strings or embeddings loses all structure. You can't ask "which version of this fact are we acting on?" or "was this fact ever revised?" The Assertion model makes those questions answerable by design.

Sleep-Phase Consolidation — Rules + Skills from Experience

Cognitive Core

Inspired by biological memory consolidation during sleep, Mnema runs a background LLM pass over all active beliefs and distils them into two typed artifacts:

  • Rules — imperative statements the agent should follow: "Use fetch_forecast(city) not get_weather() — removed in v2"
  • Skills — reusable Python functions, AST-validated, sandbox-checked, stored with execution outcomes tracked

Both are stored in a Digest — a versioned snapshot that is injected into the agent's prompt at inference time. Version 1, 2, 3... each is preserved for audit.

# The consolidation flow:
active_beliefs = store.current_beliefs(agent_id)   # what it knows now
rule_proposals = llm.extract_rules(beliefs)         # LLM distills
contradiction_proposals = llm.detect_contradictions(beliefs)
skill_proposals = llm.extract_skills(beliefs)
digest = Digest(version=n, rules=rules, skills=skills)
store.save_digest(digest)   # WAL event + atomic persist
Consolidation complete — rules updated to v3 Rules: 1 Skills: 1 Digest version: 3
Why this matters: Raw observations are noisy — the agent saw 50 API calls, some correct, some from error messages. Consolidation separates signal from noise and produces clean, typed Rules. The E1 benchmark showed this gives a 50-percentage-point lift over raw retrieval on drifting APIs.
vs. competitors
MemGPT does summarization but produces unstructured text blobs. Mnema produces typed, provenance-linked Rule and Skill objects that can be individually traced, retracted, and versioned.

Retraction Cascade — Safe Belief Withdrawal

Safety Feature

When a belief is retracted — because it was wrong, outdated, or superseded by new information — Mnema automatically asks: which Rules and Skills were derived from this belief? Those are now "at risk."

# When you retract a belief:
client.retract(assertion_id)

# Mnema traces the dependency graph and returns:
at_risk = client.retraction_cascade(assertion_id)
# → ["rule_abc123", "skill_def456"]
# These rules/skills were derived from the retracted fact.
# They're not deleted — they're flagged for re-consolidation.

The retraction also auto-resolves any open contradiction involving the retracted assertion — because if one side of a conflict is gone, the conflict dissolves.

Why this matters: In every other system, retracting a fact leaves orphaned rules silently acting on stale knowledge. The agent keeps calling a removed API endpoint because the Rule was derived from an observation that no longer exists — but nobody told the Rule. Cascade retraction surfaces this risk immediately.
vs. competitors
No competitor has retraction cascade. Zep, Mem0, MemGPT, LangMem all have mutable memory with no dependency tracking. Orphaned rules are invisible.

Typed Temporal Graph — Contradiction Detection + Resolution

Graph Layer · v0.1

This is the most novel feature built. During sleep-phase consolidation, the LLM scans all active beliefs and flags pairs that directly contradict each other. These are stored as contradicts edges in a typed temporal graph.

A contradiction is not silently discarded — it enters an OPEN → RESOLVED lifecycle. The agent should not act on conflicting beliefs until a human or policy resolves the conflict with an explicit note.

# Full contradiction lifecycle:

# 1. LLM detects during consolidation (automatic)
SleepConsolidator(store, llm).consolidate(agent_id)
# → "Detected 1 contradiction: rate limit 100 rpm vs 60 rpm"

# 2. Surface all open conflicts
conflicts = client.open_contradictions()
# → [{from_statement: "100 rpm", to_statement: "60 rpm",
#     reason: "Two conflicting rate limit values."}]

# 3. Human resolves with a permanent note (audit trail)
client.resolve_contradiction(
    rel_id,
    note="60 rpm is correct — confirmed in API changelog v2.1."
)

# 4. Integrity is clean again
client.contradiction_summary()
# → {knowledge_integrity: "clean", open_contradictions: 0}
-- Before consolidation -- Integrity: clean -- After consolidation (LLM detected contradiction) -- Integrity: conflicts_present Open contradictions: 1 Conflict: Two conflicting rate limit values: 100 rpm vs 60 rpm. A: Rate limit is 100 rpm B: Rate limit is 60 rpm -- After resolution -- Integrity: clean Open contradictions: 0
Why this matters: Every agent that observes a changing world will eventually hold contradictory beliefs. Every existing system lets those contradictions coexist silently — the agent picks one at random depending on retrieval order. Mnema makes contradictions visible, demands resolution, and records who decided and why.
vs. competitors
Zero competitors have this. Not Zep, not Mem0, not MemGPT, not LangMem. This is a first.

Semantic Retrieval — The Embedder Stack

Retrieval

Mnema ranks active beliefs by semantic similarity to a free-text query, not just exact keyword match. The embedder is pluggable — Mnema auto-selects the best available option at startup:

# Priority order (auto-detected at MnemaClient init):
1. OllamaEmbedder              # 768-dim dense, nomic-embed-text
                              # True semantic understanding
                              # Requires: ollama pull nomic-embed-text

2. SentenceTransformerEmbedder # 384-dim, all-MiniLM-L6-v2
                              # Local model, no server needed
                              # Requires: pip install mnema[embed]

3. TfidfEmbedder               # Pure stdlib, always available
                              # Bag-of-words fallback

The semantic difference is measurable. On a 6-question test with 6 assertions:

Query: "how do I authenticate with the API?" TF-IDF [0.121 → WRONG doc] — "authenticate" ≠ "Authentication" Ollama [0.601 → CORRECT] — maps synonyms via 768-dim space Overall accuracy: TF-IDF: 4/6 (67%) Ollama: 5/6 (83%)
Why the stack matters: If Ollama isn't running, the system degrades gracefully to TF-IDF rather than crashing. When Ollama is available (which it is, since it's already running the LLM), you get dense semantic retrieval for free — no new infrastructure, no API key, no cost.

Digest Injection — Prompt Memory Block

Integration

The output of sleep-phase consolidation is a Digest — a versioned, character-budget-aware markdown block that is injected into the agent's system prompt at the start of every inference call.

This is the mechanism that closes the loop: observations go in during experience, the Digest comes out for use during inference.

# At agent startup, before any user message:
memory_block = client.inject()   # renders latest Digest as markdown
system_prompt = f"""
You are an API integration agent.

## What you know:
{memory_block}

Now answer the user's question.
"""

# memory_block contains the distilled rules and skills,
# not raw observations — cleaner, more reliable.

The character budget is configurable (MNEMA_DIGEST_MAX_CHARS, default 4000) so it never overflows the context window. Older rules are dropped gracefully when the budget is tight.

MnemaClient SDK — 3-Line Integration

Developer Experience

The entire system is accessible through one object. The minimal integration is three lines:

from mnema.integrations.sdk import MnemaClient

client = MnemaClient(agent_id="my-agent")  # auto-selects embedder + LLM
client.observe("Rate limit is 60 rpm", subject="api")
system_prompt += client.inject()             # inject Digest into prompt

The full surface covers every feature:

# Core lifecycle
client.observe(statement, subject=...)       # record a belief
client.revise(prior_id, statement=...)       # update with supersession
client.retract(assertion_id)                 # withdraw + auto-cascade
client.consolidate()                         # run sleep phase
client.inject()                              # get prompt block

# Retrieval
client.search("how do I authenticate?", top_k=5)  # semantic search

# Audit
client.why(assertion_id)                     # full provenance chain
client.diff(v1=1, v2=2)                    # what changed between digests
client.report()                              # full compliance report

# Graph / contradiction
client.open_contradictions()                 # surface all conflicts
client.resolve_contradiction(rel_id, note="60 rpm confirmed")
client.contradiction_summary()              # clean or conflicts_present

# Safety
client.retraction_cascade(assertion_id)     # what breaks if I retract this?
Config is all env vars: MNEMA_DB_URL, MNEMA_OLLAMA_HOST, MNEMA_OLLAMA_MODEL, MNEMA_EMBED_MODEL, MNEMA_API_KEY, MNEMA_DEFAULT_NAMESPACE, MNEMA_DIGEST_MAX_CHARS. No hardcoded values anywhere in the codebase.

E1 Benchmark — Consolidation vs Retrieval vs Frozen

Benchmark Results

The E1 (LTCF-Bench) experiment measured three arms on a drifting API scenario across three phases:

  • A0 — Frozen: agent with static knowledge, no updates
  • A1 — Retrieval: naive last-observation pattern matching
  • A2 — Mnema: full observe → sleep-consolidate → inject cycle
E1: LTCF-Bench — Lifetime Cognitive Fitness Benchmark ============================================================== Arm v1 (%) v2 (%) v3 (%) Overall ------------------------------------------------------ A0 100.0% 0.0% 0.0% 33.3% A1 100.0% 0.0% 100.0% 66.7% A2 100.0% 100.0% 100.0% 100.0% ------------------------------------------------------ Consolidation lift (drift phases only): A0: 0.0% A1: 50.0% A2: 100.0% A2 lift over A1: +50.0pp ← the consolidation premium

Why A1 fails on v2: it sees observations like "get_weather() raised DeprecationWarning" in error context and still pattern-matches to the old API call. Consolidation sees through the noise and produces a clean rule: "Use fetch_forecast(city) — get_weather() removed in v2."

Why A2 gets v3 right immediately: the Digest from v2 consolidation is superseded by v3 consolidation. The agent starts every v3 task with the correct rule already in its system prompt.

What this proves: Structured knowledge (typed Rules in a Digest) beats unstructured retrieval on drifting environments. The 50pp consolidation premium is not a tuning artifact — it reflects the fundamental difference between retrieving raw observations and injecting distilled knowledge.
